Skylark Founder BI Copilot — Frontend Integration Contract
Version: 0.1 (target HTTP contract)
Last reviewed: 2026-08-30

IMPORTANT CURRENT STATUS
------------------------
The current project is a Streamlit application, not an HTTP API service.
There is no main.py, FastAPI/Flask server, router, or JSON endpoint in this
repository today. The existing UI calls BIAgent.send_message() in-process and
receives a plain text response.

Therefore, the endpoints below are the contract to implement in a backend API
adapter before a separate frontend integrates. A frontend MUST NOT invent
endpoints or call Monday.com directly.

Current backend capabilities available for the API adapter:
- get_available_boards()
- get_board_schema(board_id)
- fetch_board_data_sample(board_id)
- calculate_metrics(board_id, group_by_column, sum_column)
- calculate_pipeline(board_id, group_by_column, weighted, period)
- get_leadership_update()
- BIAgent.send_message(message) -> plain-text LLM response


ARCHITECTURE
------------
Frontend -> Skylark backend API -> Monday.com GraphQL API
                                  -> Gemini via BIAgent

Never expose MONDAY_API_TOKEN or GEMINI_API_KEY to the browser.


BACKEND CONFIGURATION
---------------------
Development backend base URL: http://localhost:8000
Production backend base URL: supplied through the frontend environment

Frontend environment variable (React/Vite example):
VITE_API_BASE_URL=http://localhost:8000

Prototype authentication: none.
The backend owns Monday.com and Gemini authentication.

CORS origins to allow:
- http://localhost:5173 (Vite default)
- deployed frontend URL


STANDARD RESPONSE RULES
-----------------------
- Content-Type: application/json
- Money values are numeric INR values, never pre-formatted strings.
- Dates use ISO-8601 strings. Date-only values use YYYY-MM-DD.
- Percentages are 0-100 numbers: 31 means 31%, not 0.31.
- Chart series use arrays of objects, not maps/dictionaries.
- All aggregation responses include data-quality information.
- The frontend formats currency:
  * below 100,000: INR with standard separators
  * 100,000 to below 10,000,000: INR lakhs (for example, INR 12.50 L)
  * 10,000,000 and above: INR crores (for example, INR 1.25 Cr)

Standard error response (non-2xx):
{
  "error": {
    "code": "MONDAY_CONNECTION_FAILED",
    "message": "Unable to retrieve Work Orders data.",
    "retryable": true
  }
}

Error codes:
- AUTHENTICATION_ERROR: show a configuration warning; do not retry automatically.
- MONDAY_CONNECTION_FAILED: show warning banner and a Retry action.
- RATE_LIMITED: show a retry-after/loading state and Retry action.
- BOARD_NOT_FOUND: show an explanatory empty state.
- INVALID_REQUEST: show the message near the relevant filter/input.
- NO_DATA_FOUND: show an empty state, not an error toast.
- DATA_QUALITY_ERROR: show results with a prominent caveat.
- INTERNAL_ERROR: show a generic retryable error; never expose exception details.

adapter must create this structured response; do not claim these fields exist

Conversation behaviour:
- First message sends conversation_id: null.
- Backend returns conversation_id.
- Later messages must return that ID in the request.
- Current Streamlit/Gemini session memory is in-process only. A separate
  frontend requires backend-managed conversation storage keyed by this ID.
- Use normal request/response JSON for this prototype. Do not implement SSE,
  WebSockets, or token streaming unless the backend explicitly adds it.

FRONTEND PAGES
--------------
1. Executive Dashboard — KPI cards, funnel, sector chart, risks.
2. BI Chat — conversation UI using POST /api/chat and conversation_id.
3. Pipeline Deep Dive — period/sector/owner/stage filters and tables/charts.
4. Operations — work-order status, backlog, delayed-project views.
5. Leadership Brief — generate and display printable leadership summaries.

Required UI states for every remote view:
- Loading: "Retrieving Monday.com data..." then "Running business analysis..."
- Error: map the standard error code to the behaviour above.
- Empty: explain that no records matched the selected filters.
- Data-quality warning: retain results and show the warnings next to them.
- Freshness: show last_refresh or generated_at near dashboard/brief results.
